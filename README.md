🧪 Problem Format

Every solution should aim to follow the same learning structure:
```text
Problem
   ↓
Understanding
   ↓
Approach
   ↓
Implementation
   ↓
Example
   ↓
Time Complexity
   ↓
Space Complexity
```
Example
# Reverse a String

## Problem

Reverse the given string.

## Example

Input:
hello

Output:
olleh

## Approach

Use two pointers, slicing, or iteration.

## Complexity

Time: O(n)

Space: O(n)


The goal is not just to store code.

The goal is to document how the solution was understood.

⏱️ Complexity Cheat Sheet

O(1) — Constant
Example: Array access

O(log n) — Logarithmic
Example: Binary Search

O(n) — Linear
Example: Linear Search

O(n log n) — Linearithmic
Example: Merge Sort

O(n²) — Quadratic
Example: Bubble Sort

O(2ⁿ) — Exponential
Example: Generating Subsequences

O(n!) — Factorial
Example: Generating Permutations

🎓 Learning Philosophy
01 — Understand Before Memorizing

Don't memorize solutions.

Understand:

Why does this work?

A solution you understand can be adapted to new problems.

02 — Start With Brute Force

A slow correct solution is better than a fast solution you don't understand.

First solve the problem.

Then improve it.

03 — Optimize Consciously

After getting a working solution, ask:

Can I reduce the time complexity?

Then ask:

Can I reduce the space complexity?

Optimization should be intentional, not accidental.

04 — Learn Patterns

If you solve ten problems using the same idea, you've learned something more valuable than ten isolated solutions.

Look for recurring techniques:

Two Pointers
Sliding Window
Hashing
Binary Search
Recursion
Backtracking
BFS / DFS
Dynamic Programming
05 — Keep Moving

Some problems will take 10 minutes.

Some will take 2 hours.

Both count.

The important thing is to keep learning and moving forward.
